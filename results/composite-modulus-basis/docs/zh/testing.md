# 测试、覆盖范围与复现

[English](../en/testing.md) · [返回说明](../../README.md) · [Lean 证明](formalization.md)

测试检查参考程序，不能代替一般性数学证明。核心 Lean 定理不依赖这些测试，
也不受下面列出的质数、维度和长度范围限制。

## 1. 运行命令

Python 3.10+，只依赖标准库。在本目录执行：

```sh
python3 implementation/test_solver.py                 # 全部测试
python3 implementation/test_solver.py --suite small   # 原有小规模穷举、元数据、原型与一般环测试
python3 implementation/test_solver.py --suite large   # 大模数独立验证
python3 formal/verify.py --regression    # 一般证明、公理检查及有限 Lean 回归
python3 implementation/benchmark.py                  # 三组性能样例
```

测试使用 `assert`，入口拒绝 `python -O`。测试失败会返回非零状态，并尽可能打印
参数、区间及目标。大参数随机种子为 `20260915`，小参数主种子为 `20260912`；
元数据、原型和一般环测试分别使用代码中固定的独立种子。

刷新实测报告：

```sh
python3 implementation/test_solver.py > artifacts/tests.txt 2>&1
python3 formal/verify.py --regression > artifacts/lean.txt 2>&1
python3 implementation/benchmark.py > artifacts/benchmarks.txt 2>&1
```

时间与机器、Python 版本和负载有关；日志中的检查数量和答案由固定种子决定。

## 2. 为什么保留小质数穷举

小模数可以枚举全部系数和目标，直接按线性组合定义产生答案。
这能系统检查大量边界，不能仅为增大质数而移除。
原有完整序列穷举包括：

| 模数 | 维度 | 序列长度 |
|---:|---:|---:|
| 4 | 2 | 3 |
| 8 | 1 | 4 |
| 2 | 2 | 4 |
| 6 | 1 | 3 |
| 12 | 1 | 2 |

另有模 1、4、5、6、8、9、12、18 的随机序列完整目标枚举、
逐时间幂层身份与操作上界检查、1,200 组显式闭包原型对照，以及三个小有限环的归约测试。

## 3. 大质数、深幂层和 CRT

每个固定测试质数都由测试中的独立试除法验证，不调用待测程序的分解函数。
质数最大为 **2,147,483,647**，并覆盖 OI 常用的 **998,244,353** 和 **1,000,000,007**。

| 模数或分解 | 模数位数 |
|---|---:|
| $17$ | 5 |
| $97^2$ | 14 |
| $257^4$ | 33 |
| $65537$ | 17 |
| $65537^3$ | 49 |
| $998244353$ | 30 |
| $998244353^2$ | 60 |
| $1000000007^3$ | 90 |
| $2147483647^2$ | 62 |
| $2^{64}$ | 65 |
| $3^{20}$ | 32 |
| $2^{12}\cdot97^3\cdot65537$ | 48 |
| $998244353^2\cdot1000000007^2$ | 120 |

这里“位数”是正整数的二进制长度，所以 $2^{64}$ 是 65 位整数。
大模数均显式传入已知分解，避免把时间花在试除分解上。
测试维度包括 1、2、4、8、12，序列长度为 24 或 32；性能样例另覆盖维度 16、长度 4,000。

### 独立参考答案

1. **整数格 oracle**（`implementation/tests/oracles.py`）。把模 $m$ 成员关系化为整数格
   $\operatorname{span}_{\mathbb Z}(a_l,\ldots,a_r,mI_d)$ 的成员关系。
   用扩展 gcd 和行列式为 1 的整数行变换构造三角基，再做整数回代。
   它不使用素因子分解、时间戳、幂层或被测消元算法。未处理坐标上的 $mI_d$ 行
   允许约减中间值，避免大整数膨胀。格指数也独立给出生成子模的大小。
   这个 oracle 本身先与小模数系数枚举核对了 **4,656** 个目标。
2. **可解析构造**。从坐标轴上的生成元出发，各坐标理想由对应系数与 $m$ 的 gcd 决定。
   对输入和目标同时施加已知可逆的整数坐标变换，保持答案，同时得到稠密数据。
   预期答案和子模大小不需要运行任何消元；这些大模数构造也反过来检查整数格 oracle，
   另核对 9,484 个目标。
3. **一维 gcd oracle**。对每个区间直接计算
   $g=\gcd(m,a_l,\ldots,a_r)$，检查 $g\mid x$，子模大小为 $m/g$。
   在较大模数下也检查全部区间。

### 数据不是只有随机满秩

数据包含零行、重复行、非单位倍数、耦合的零化关系、低秩组合，以及新后缀缺少某些坐标的情况。
目标既有显式线性组合，也有独立随机向量、单位向量和构造出的非成员。
每组模数都要求实际出现 YES 和 NO。

每条查询在追加时、后续追加后的历史版本以及离线接口上核对；同时检查 `span_size`。
每次追加验证列访问、弹出、槽位写入和消元次数，以及含输入规范化与幂链生成的
`3kd²` 坐标更新额度。操作次数断言是实现回归检查，一般上界由 Lean 与数学证明给出。

## 4. 实测统计

本次整理记录于 2026-09-15，实际输出见 [test_results.txt](../../artifacts/tests.txt)。

| 测试组 | 统计 |
|---|---|
| 原有系数枚举主测试 | 9,278 个序列、79,694 个区间、5,959,998 次成员关系断言 |
| 一般有限环归约 | 153,600 次断言，作为额外扩展测试 |
| 新增大模数测试 | 78 个序列、9,332 个区间、240,420 次成员关系断言 |
| 大模数区间构成 | 整数格 4,296；可解析构造 1,136；一维 gcd 3,900 |
| 大模数查询答案 | 46,386 个 YES、33,754 个 NO，共 80,140 条查询用例 |

成员关系断言包含三个接口/阶段对同一查询的核对，不是等量独立输入。
元数据检查、原型对照和 oracle 自检单独列出，未混入主测试的序列与区间计数。

## 5. 性能样例

[benchmark.py](../../implementation/benchmark.py) 对以下三个模数使用固定种子 `120926`：

- $72=2^3\cdot3^2$；
- $1000000007^2$；
- $998244353^2\cdot1000000007^2$。

默认 `n=4000, d=16, q=8000`，包含显式成员目标和随机目标。
计时只包围离线求解，数据生成、参考答案抽查和另行操作计数检查在计时之外。
每组从结果中每隔 97 条抽查一次，共 83 条，与整数格 oracle 对照。
这不是每个性能查询都有独立验证，更不是最坏情况时间证明。

可以调整规模，例如：

```sh
python3 implementation/benchmark.py --case large-crt --n 1000 --dimension 12 --queries 2000
```

本机时间、YES/NO 数量和操作统计见 [benchmark_results.txt](../../artifacts/benchmarks.txt)。
